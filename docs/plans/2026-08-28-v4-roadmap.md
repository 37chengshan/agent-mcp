## 1. 核心定位与不可违反原则

**agent-mcp = Agent Control Plane / Orchestrator / Runtime Gateway**：负责「在哪里运行、何时运行、为什么继续、如何调度、如何恢复、如何观察、如何治理」；**绝不承担**「如何执行 Agent」。

边界：思考 / 工具调用 / 代码执行 / 模型推理 → Native Runtime；编排、调度、托管、观测、治理、可靠生命周期 → agent-mcp；协议接入 → Backend Adapter。agent-mcp 不是新 Agent Runtime、新 Coding Agent、prime-agent 替代品、Claude Code/Codex 复制品、统一模型运行时。

不可违反原则（写进 docs 与测试）：
- P1 显式指派：用户显式指定 target_cli × model；系统永不擅自换底座，不引入 cli:"auto"。
- P2 执行留在原生：agent-mcp 不实现 agent loop；任何「继续执行」都经 Backend Adapter 驱动 Native Runtime。
- P3 单一执行单位：一切触发最终创建统一唯一的 Run/Execution，禁止多套并行 runner/状态机。
- P4 协议三界分立：MCP Protocol ≠ agent-mcp Control Protocol ≠ Backend Protocol，互不混写。
- P5 会话解耦：应用状态不依赖 Mcp-Session-Id；跨调用一律显式 handle（agent_id/run_id/goal_id/schedule_id）。
- P6 预算即事实：预算耗尽 = INCOMPLETE ≠ 成功；Goal 完成不再产生 continuation；任一预算不可突破。
- P7 幂等与可恢复：同一 command 最多一次真实执行；crash 后不重复、不丢失、可恢复。
- P8 能力可信：Adapter 只调用真实协商出的 capability；三态 SUPPORTED/UNSUPPORTED/DEGRADED。
- P9 知识可审计：base system prompt 不可变；harness 修改走 revision+快照+provenance；global 显式授权。
- P10 吸收有界：只吸收 prime-agent 中属于 Control Plane 的设计思想；不吸收 TUI/provider-auth/模型运行时/RLM 完整运行时/package execution env。

## 2. 总体架构

```
MCP Protocol Layer（mcp_server.py）─ 2025-03-26│2025-11-25│2026-07-28（stateless/discover/MRTR/Tasks）
        │ 显式 handle（agent_id/run_id/task_id）
agent-mcp Control Plane（daemon_http.py）─ /api/v4/command + command_journal；{generation,seq}；snapshot；/api/protocol
        │
Execution Manager（agent_mcp/execution.py）─ Run（唯一执行单位）：admission/queue/slot/worker bind/retry/continuation/恢复
        │
Trigger / Policy（triggers.py + policies/）─ Goal/Schedule/Heartbeat/Manual（Intent）；Autonomous/Retry/Budget（只约束 Run）
        │
Backend Adapter（cli_adapters.py）─ Claude/Codex/omp/…/PRIME-AGENT-RPC/PRIME-AGENT-ACP/ACP Agent/Generic（能力契约）
        ▼
Native Agent Runtime（执行真正发生在这一层）
```

## 3. Core Object Model

Trigger/Intent（Goal/Schedule/Heartbeat/Manual Follow-up）只产 Intent，不直接管理 worker；ExecutionPolicy（AutonomousPolicy/RetryPolicy/BudgetPolicy）是一次 Run 的纯声明策略；Run/Execution 是唯一执行单位（runs 表）；Worker/Session 是 agents 行（兼容保留，由 Run 引用）；BackendAdapter 是能力契约。

runs 表：id(PK uuid)/run_kind/trigger_type/trigger_ref/policy_json/status/stop_reason/agent_id/parent_run_id/origin_command_id/attempts/error_fingerprint/created_at/updated_at/completed_at。

MCP 兼容投影：Run.status → 既有 agent.status/stop_reason（兼容层映射，MCP 工具语义不变）。

## 4. Execution State Machine（唯一状态机）

PENDING → ADMITTED → RUNNING ⇄ WAITING → COMPLETED│FAILED│CANCELLED│INTERRUPTED│INCOMPLETE

规则：Goal completed 不再 continuation；同一 schedule tick 至多一个 Run；同一 command 至多一次真实执行；Autonomous 任一预算不可突破（min() 生效）；预算耗尽 ≠ 成功。

## 5. MCP 2025-11-25 / 2026-07-28 Compatibility Architecture

已实现基线：mcp_server.py 支持版本集 [2026-07-28, 2025-11-25, 2025-03-26]（initialize 顶层协商、_meta+server/discover、tasks 双路径能力识别、input_required 闭环；DSH SDK 1.29.0 实测 2025-11-25）。

v4 分层原则：MCP 层无状态；agent-mcp 应用层有持久状态（Control Plane），不藏进 transport session；兼容层独立、不污染 Execution Model；Mcp-Session-Id 不外溢。

**MCP Task ≠ agent-mcp Run**：MCP Task 是协议层 long-running interaction handle（get/update/cancel/input_required）；Run 是内部实际 Agent Execution。映射 task_id ↔ run_id 只读关联（进程内注册表 + tasks 表持久化）；tasks/get=run 状态投影、tasks/update(inputResponses)→steer、tasks/cancel→interrupt。不重复造平行长任务协议。

兼容性矩阵（测试驱动）：protocol negotiation / session semantics / stateless requests / capability discovery / tool calls / long-running task / explicit handles / SSE & Streamable HTTP / reconnect / legacy client 行为——2025-11-25 与 2026-07-28 双列验证（streamable-http transport 为 P2 既有项，列 Phase 6 候选）。

## 6. Control Plane Protocol

协议三界：MCP Protocol（mcp_server.py）｜agent-mcp Control Protocol（daemon_http.py：/api/v4/command、/api/v4/ack、/api/protocol、/api/snapshot、/events）｜Backend Protocol（适配器）。

命令信封：{protocol:"v4", client_id, command_id, request_hash, method, params, meta}。v1 端点保持不变；新增能力走 v4 + capability gate。

Journal 字段：id/client_id/command_id/request_hash/method/params_json/state(recorded|completed|uncertain|acked)/result_json/created_at/completed_at。

幂等规则：同 (client_id, command_id, request_hash) → 返回已记录结果；同 id 不同 hash → command_id_conflict（绝不执行）；已接收无持久结果 → uncertain（不盲目重放）。

压缩：journal → ack（客户端确认）→ watermark → compaction（仅 ≤ 水位且 acked），**禁 LRU 删除破坏幂等**。

事件游标：Event ID = {generation, seq}；generation = 持久化 epoch（meta.gen_epoch 每次 daemon 启动 +1 + 随机 nonce），禁仅内存整数；SSE Last-Event-ID 续播；区间不可得回退快照（begin/chunk/end，512KiB/chunk，>4MiB 落盘缓存）；backpressure attachment-local。

能力协商：GET /api/protocol → {version:4, schema_revision, capabilities, adapters:{...}}；capability-gated；旧→新、新→旧双测。

## 7. Execution Manager

agent_mcp/execution.py：create_run → admission（policy + SlotScheduler）→ worker bind → run（复用 _run_worker/_worker_watcher）→ advance → 终态/恢复。agent_mcp/triggers.py：GoalManager/ScheduleManager（heartbeat=schedule kind）只产 Intent。Dispatcher 收敛为入口适配层，19 个 MCP 工具行为不变。

触发 → Run 唯一路径：[Goal continuation/Schedule tick/Heartbeat wakeup/Manual follow-up/Retry/Autonomous cont.] → Intent → ExecutionManager.create_run(policy) → admission → bind worker → RUNNING → 终端态。

关键语义：goal completed 停止续播；预算耗尽=INCOMPLETE；gate 失败有界回投且工作区 git 指纹未变不重跑同一失败 gate；tick claim 先于 delivery；usage 归因折叠（child_usage_attributed；get_token_usage 增 include_children）；daemon 重启从 runs 表恢复。

## 8. Harness / Refinement

Harness = agent-mcp 管理的可审计能力与知识资产层（prompt/memory/skill/subagent_spec）。Revision-based：metadata/revision/provenance → DB；大件/skill 包 → filesystem artifact store；单一 source of truth；project_memory 降级为兼容 API。支持 expected_version（乐观并发）、rollback（不丢历史 revision）、diff、provenance。

工具面：harness_list/harness_add/harness_update/harness_delete/harness_rollback。

refine 管道（禁 reviewer 直写）：trajectory → reviewer Run（经 ExecutionManager）→ refinement proposal → schema validation → authorization（global 显式授权；base prompt 不可写）→ conflict check（expected_version）→ diff → transactional commit → revision → event。保护：failure fingerprint + session fingerprint + refinement budget + cooldown + same-failure suppression。工具面：refine_preview/refine_commit/refine_rollback。

Skill/Subagent Spec：SKILL.md frontmatter 校验（name/description/version）；skill 描述注入 task brief；role= 引用 subagent 规格。

## 9. Prime Agent 适配器架构

Prime Agent = 重要 Backend Runtime。吸收控制面思想：persistent goals/schedule/heartbeat/bounded autonomous/continual harness（概念）/refine（概念）/agent-to-agent messaging/daemon reliability/RPC/ACP。不吸收：TUI/provider-auth/模型 Runtime/完整 RLM Runtime/完整 package execution env。

双适配器：PrimeAgentRPCAdapter（LF JSONL RPC；spawn/resume/steer/follow_up/observe/usage；usage_semantics=authoritative）与 PrimeAgentACPAdapter（ACP client，gate）。能力契约每项经真实协议协商判定 SUPPORTED/UNSUPPORTED/DEGRADED，写入 capability-matrix；DEGRADED 必须写明降级行为；未安装/版本过旧 → 结构化 400 + 指引。

**D3 / 内置 RLM 明确排除 v4.0**：built-in kernel/RLM 只作 v4.1+ 独立 RFC/Experimental Runtime。理由：内置 RLM = Control Plane + Agent Runtime + Persistent REPL + Package Environment + Recursive Runtime 五合一，改变产品定位，违反 §1 边界。

## 12. Failure Injection Matrix

F1 journal 写入后 crash → 幂等不重复执行；F2 accepted 后 worker crash → 恢复不重复 spawn；F3 worker 完成但 event 丢失 → 快照回退补齐；F4 SSE disconnect → attachment-local + 续播/快照；F5 generation reconnect → 旧代拒绝/去重；F6 schedule claim 后 crash → 不产生第二个 Run；F7 goal continuation 后 crash → 续播一次且仅一次；F8 backend RPC disconnect → FAILED/按 policy 重试；F9 prime-agent restart → RPC 重连 + DEGRADED 广播；F10 refine commit 中途失败 → 事务回滚无半提交；F11 rollback 中途失败 → 历史 revision 不丢；F12 snapshot 大数据恢复 → 分块流式有界内存。

装置：tests/fault_hooks.py + crash points（after_journal_write/after_admit/before_event/after_tick_claim/after_gate/mid_refine_commit/mid_rollback/snapshot_stream）。

## 13. 系统 Invariants（tests/test_invariants.py）

1. 同一 (client_id, command_id, request_hash) 最多一次真实 execution。
2. command_id 与不同 request_hash 冲突时绝不再次执行。
3. 同一 schedule tick 最多创建一个 Run。
4. Goal completed 后不得自动 continuation。
5. Autonomous 永远不能突破任一预算（continuation/turn/token/time）。
6. Adapter 不得调用未声明 capability。
7. base system prompt 永不被 refine 修改。
8. Harness revision rollback 不得丢失历史 revision。
9. daemon 重启不产生 event generation collision。
10. MCP protocol session 与 agent-mcp application state 解耦。

## 15. 原草案删除/延后/重构

重构：A 轨「内部映射 v4 命令」→ 明确内部控制协议（≠重实现 MCP）；B 轨各自 continuation → Run+ExecutionManager 统一；schedules 单独循环 → triggers.py→execution.pump()；project_memory 独立模型 → harness 兼容 API；refine 直写 → proposal 管道；单 prime-agent adapter → 双适配器三态；「双版本兼容」仅版本号 → 独立 compatibility layer + 矩阵 + Tasks↔Run 映射。

## 18. 核心问题回答

agent-mcp 以 Control Plane 身份，把用户意图统一翻译为 Run/Execution，经 Execution Manager 以同一套 admission/queue/slot/worker-binding/continuation/恢复语义调度到用户指定的 Native Runtime；每个 Runtime 通过能力三态可信的 Backend Adapter 接入；执行 100% 留在原生运行时；MCP 2026-07-28 只作对外标准协议层，Tasks 只映射不替代 Run；harness/refine 只进化 agent-mcp 的知识与规格资产。任何让 agent-mcp 变成 Agent Runtime/模型平台/Runtime 复制品的设计，一律降级、隔离或延后。成功不以工具数、功能数、复用 prime-agent 功能数为标准。
